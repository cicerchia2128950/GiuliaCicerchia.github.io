Interpretation

    
    
      
  • Distribution of x and y. The histograms are essentially flat, but this comes from the algebra and not from "randomness". The map k→kG is a bijection onto the subgroup, so no point is repeated. Every x appears exactly twice (as +y and -y) and, for p = 10007, every y appears exactly once (because p ≡ 2 mod 3, the cube map is a bijection). Only about half of the possible x values are ever used (those for which x³+7 is a quadratic residue), which is why H(x) is one bit below log2 p.
    • 
      
  • Bits. The inner bits of x and y are balanced (about 0.50). The top bits are biased because the coordinates lie in [0, p-1] and p is not a power of 2: for p = 10007 < 214, the top bit is 1 only 18% of the time and the next two bits about 41%. This is a property of the encoding, not of the function.
    • 
      
  • Correlation between input and output. For p = 10007 the linear correlations between k and x or y and the lag-1 autocorrelation are all below 0.01 in absolute value: nearby private keys give public keys that look unrelated. The values for p = 17 are not meaningful because there are only 8 points. However, the scatter plot of k vs x is not structureless: it is mirror-symmetric around n/2 because x((n-k)G) = x(kG).
    • 
      
  • Avalanche-like behaviour. Flipping one bit of k changes about 48% of the output bits, close to the ideal 50% of a good hash (0.483 vs 0.500 for the reference mixing function). This must be read with care. Flipping bit i changes k by ±2i, so Q changes to Q ± 2iG, an exact algebraic relation that anyone can compute. The coordinates look very different, but the relation between the two outputs is fully known (the function is a group homomorphism). The apparent avalanche is therefore a consequence of the coordinates looking pseudo-random, not a design property.
    • 
    


    
Which properties matter for a cryptographic one-way function

    
    
      
  • Easy forward, hard backward. Q = kG costs O(log k) group operations (double-and-add), while recovering k from Q is the Elliptic Curve Discrete Logarithm Problem. The best generic attacks need about √n steps. Here the brute-force button finds k instantly because n ≤ 104; for secp256k1, n ≈ 2256 and √n ≈ 1038.
    • 
      
  • Determinism and pseudo-random-looking output inside the subgroup (no useful statistical relation between k and Q): the statistics above are meaningful as a sanity check for this.
    • 
      
  • Injectivity for k in [1, n-1]: different private keys always give different public keys.
    • 
      
  • Algebraic structure, (k1+k2)G = k1G + k2G, is not a weakness here; it is exactly what makes digital signatures, ECDH and key derivation possible.
    • 
    


    
Properties specific to cryptographic hash functions

    
    
      
  • Compression: arbitrary-length input to fixed-length output, so collisions must exist but be infeasible to find (collision resistance, second-preimage resistance). kG has no collisions on [1, n-1] and takes a number, not an arbitrary message.
    • 
      
  • A strict avalanche effect with no exploitable relation between outputs. In kG the relation Q' = Q ± 2iG is public.
    • 
      
  • No algebraic structure. A hash must not be homomorphic or have symmetries such as x(kG) = x(-kG).
    • 
      
  • Uniformity over the whole output space. The output of kG is a curve point, so only about half of the (x, y) space is occupied and every output satisfies the curve equation.
    • 
    


    
Conclusion and caveats

    
    
      
  • Scalar multiplication behaves like a one-way function because of the ECDLP, not because of hash-like mixing. Statistical tests (uniformity, correlation, avalanche) can only show that the outputs look random; they say nothing about the hardness of inverting the map.
    • 
      
  • For p ≡ 2 (mod 3), such as 17 and 10007, the curve y² = x³ + 7 is supersingular with exactly p + 1 points, which is why n = 10008. secp256k1 has p ≡ 1 (mod 3) and is an ordinary curve. This toy is for understanding the mechanics only and is not secure.
    • 
      
  • For tiny groups the statistical tests have little power (8 samples for p = 17), so the p = 10007 results are the more reliable ones.
